## How server functions work

All application operations are exported from `src/server-functions.ts`. Each one is created with `createServerFn` from `@tanstack/react-start`.

| Aspect | Behavior |
| --- | --- |
| Definition | `createServerFn({ method: "GET" })` for reads without input, `createServerFn({ method: "POST" })` for everything that accepts input or changes data |
| Input | Functions that take input declare `.validator((input: unknown) => input)`. The raw input is passed to the server module, which parses it with Zod schemas from `src/lib/validation.ts` and `src/lib/permission-schema.ts` |
| Implementation | Each handler dynamically imports its module (for example `await import("./server/requests")`) so server-only code such as `mysql2`, `googleapis`, and `node:crypto` never ships to the browser |
| Error handling | Handlers are wrapped in `runSafely`, which converts thrown errors into safe, user-facing messages |
| Authorization | Every implementation reads the session cookie and re-checks the role on the server. Client-side checks only hide controls |

<Note>
  Server functions are called from React components as typed RPCs. They are not a public REST API and must not be called by third-party systems. External integrations use the [HTTP API routes](#http-api-routes) below.
</Note>

## HTTP API routes

HTTP routes are file routes in `src/routes/api.*.ts` with `server.handlers`. All responses set `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`.

### GET /api/auth/google

Starts Google sign-in with PKCE.

| Item | Detail |
| --- | --- |
| Query | `mode` (`requisitioner` default, `hrdo`, or `external`), `redirect` (same-site path to return to) |
| Behavior | Generates a 32-byte `state` and PKCE verifier, sets short-lived httpOnly cookies, redirects to Google with `scope=openid email profile`, `code_challenge_method=S256`, `prompt=select_account` |
| Credentials | `external` mode uses `GOOGLE_EXTERNAL_CLIENT_ID`/`SECRET`, falling back to the shared client |
| Errors | `302` to `/login?error=google_unavailable` (or `/coe?error=...`) when credentials or the redirect URI are invalid |

### GET /api/auth/google/callback

Completes Google sign-in.

| Item | Detail |
| --- | --- |
| Query | `code`, `state`, or `error` from Google |
| Checks | State compared to the cookie with a constant-time check, code exchanged with the PKCE verifier, Google-verified email required, domain and role rules applied per mode |
| Success | Creates the session and redirects to the safe requested page, `/complete-profile`, or the password-change step |
| Failure | `302` to `/login`, `/hrdo/login`, or `/coe` with `error` set to `google_session`, `google_denied`, `google_unavailable`, `google_token`, `google_configuration`, `google_profile`, `google_role`, or `google_server` |

### GET /api/gmail/connect

Authorizes the HRDO sender mailbox. Local development only.

| Item | Detail |
| --- | --- |
| Availability | `404` when `NODE_ENV=production` or the host is not `localhost` or `127.0.0.1` |
| Requires | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` (localhost URL ending in `/api/gmail/callback`), `GOOGLE_SENDER_EMAIL`; otherwise `503` |
| Behavior | Sets `gmail_oauth_state` (httpOnly, `Max-Age=600`) and redirects to Google with `gmail.send` and email scopes, `access_type=offline`, `prompt=consent`, `login_hint` set to the sender |

### GET /api/gmail/callback

| Item | Detail |
| --- | --- |
| Behavior | Validates state, exchanges the code, confirms the Google account matches `GOOGLE_SENDER_EMAIL`, and writes only `GOOGLE_REFRESH_TOKEN` to `.env` |
| Responses | HTML pages: `200` on success, `404` when not local, `503` when not configured, error pages when Google returns no code or a different account |

### POST /api/sheets/webhook

Receives Late/Absences sheet changes.

```http
POST /api/sheets/webhook
Content-Type: application/json
x-webhook-secret: <LATE_ABSENCES_WEBHOOK_SECRET>
```

| Status | Body |
| --- | --- |
| `200` | `{ "ok": true, "result": { ... } }` |
| `401` | `{ "ok": false, "error": "..." }` when the secret fails authentication |
| `400` | `{ "ok": false, "error": "..." }` for any other sync failure |

The handler calls `syncFromWebhook(secret, body)` in `server/late-absences`.

### GET /api/verify-ticket/`$token`

Verifies the QR code on an official trip ticket.

| Status | Body |
| --- | --- |
| `200` | `{ "valid": true, "ticket": { ... } }` with the authoritative request date, travel dates, and destinations |
| `404` | `{ "valid": false }` |
| `503` | `{ "error": "Ticket verification is unavailable." }` |

Also sets `Referrer-Policy: no-referrer`. Tokens are HMAC-SHA256 signed with `TICKET_VERIFICATION_SECRET`. See [Security](/technical/security).
