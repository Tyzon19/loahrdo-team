LOA HRDO Desk is an integrated operational platform for Lyceum of Alabang. It brings vehicle reservation and trip-ticket processing, Certificate of Employment requests, Permission Slip processing, and late-and-absence operations into role-based web services.

## Organizational context

The Physical Facilities Management Office operates vehicle reservation and trip-ticket services. HRDO operates employee Certificate of Employment and attendance-related services. The platform gives each office an independent workflow while sharing institutional authentication, account management, MySQL data, notification delivery, and administrative oversight.

## Current process and problems addressed

The replacement system removes or reduces paper routing, scattered records, manual status tracking, duplicate account data, and inconsistent document delivery. Request owners, approvers, and administrators can view the current state and retained history from a central application.

## Purpose

The system standardizes request submission, approval, document generation, record retention, notifications, and role-specific administration across the included employee-service modules.

## Objectives

- Provide authenticated institutional and eligible external user access.
- Automate validation and sequential approval workflows.
- Generate official trip tickets and COE-related documents.
- Maintain signatures, decision history, and audit messages.
- Restrict operations through server-side role checks.
- Provide search, archive, analytics, receipts, and reporting.
- Preserve records for authorized operational use.
- Send Gmail notifications and official attachments.
- Support desktop and mobile browser use.

| Transport Head | `transport_head` | Review vehicle requests; assign fleet resources; initial workflow signatory | - | R | - | - | - |
| Director | `director` | Recommend or approve assigned workflow stages | - | R | - | - | - |

| Transport Staff | `transport_staff` | Operational and dispatch support | - | - | - | - | R |
| Guard | `guard` | Record time out and time in on dispatch forms | - | - | - | - | R |
| Driver | `driver` | Record odometer readings and trip reports | - | - | - | - | R |
| Assistant | `assistant` | Alternate signatory for configured stages | - | R | - | - | - |
| Administrator | `admin` | Manage module records, users, signatories, reports, and configuration | - | - | A | R | A |
| Super Administrator | `is_super_admin` | Manage organization-wide system access and cross-module oversight | - | - | A | A | R |

<Note>
  R = Responsible (performs the work), A = Accountable (approves or owns the outcome), - = not involved.
</Note>

## Scope

### In scope

- Account authentication (password, OTP, Google OAuth).
- Account profiles, password recovery, and forced password changes.
- Role dashboards and request queues.
- Vehicle request submission, approval chain, return, resubmission, and dispatch.
- Certificate of Employment request, verification, processing, correction, and release.
- Permission Slip submission, director approval, receipt generation, and email delivery.
- Late and absence attendance synchronization, mapping, discrepancy flags, and notifications.
- Electronic signatures, decision history, and audit records.
- Official trip tickets, QR verification, receipt archives, and bulk downloads.
- Gmail API notification delivery and Google Sheets integration.
- Analytics, reporting, and trip archive search.

### Out of scope

- Payroll computation or policy enforcement.
- Legal document drafting outside COE templates.
- Decisions that remain under institutional authority.
- General HR information systems not related to the four modules.

## Software development life cycle

<Note>
  The phases below reflect the delivery practices evidenced in the repository: Zod schema validation, Vitest unit and routing suites, `db:setup` and `db:seed` automation scripts, ESLint and Prettier enforcement, and iterative feature increments per module.
</Note>

| Phase | Activities | Key artifacts |
| :-- | :-- | :-- |
| Planning | Define module boundaries, role maps, and integration points. | Project scope, stakeholder matrix, architecture decisions. |
| Requirements | Document workflows (VRTT, COE, Permission Slip, attendance), validation rules, and notification triggers. | Workflow tables, status enums, access rules, acceptance criteria. |
| Design | Design database schema, API contracts, session stores, and security headers. | ERD, server-function signatures, route guards, CSP policy. |
| Implementation | Build React 19 + TanStack Start routes, server functions, Zod validators, and Radix UI components. | Source code in `src/routes`, `src/server-functions.ts`, `src/lib/*`. |
| Testing | Run Vitest suites covering access rules, workflow transitions, validation, email templates, OAuth, and ticket verification. | `src/test/*.test.ts` (~160 cases across 24 files), CI pass. |
| Deployment | Run `npm run build`, configure environment variables, execute `db:setup`, authorize Gmail sender, and verify OAuth callbacks. | `.env`, production build, database schema, deployment checklist. |
| Maintenance | Monitor logs, failed emails, sync errors, session trends, and disk use; apply backups and schema updates. | Backup scripts, sync logs, incident records, release notes. |
