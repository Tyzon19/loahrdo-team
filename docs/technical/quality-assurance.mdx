The LOA HRDO system is tested with an automated suite of 161 cases across 23 test files, plus manual user acceptance testing before each release. All tests run in Vitest with jsdom and Testing Library.

## Test strategy and tooling

The project uses **Vitest** as the test runner with the following stack:

| Tool | Purpose |
| --- | --- |
| Vitest | Test runner and assertion library |
| jsdom | Browser-like DOM environment for component tests |
| @testing-library/react | React component queries and user-event simulation |
| @testing-library/jest-dom | Custom DOM matchers (`toBeInTheDocument`, etc.) |

### Commands

```bash
# Run the full suite once
npm test

# Run in watch mode during development
npm run test:watch

# Lint and format checks
npm run lint
npm run format
```

### Configuration

`vitest.config.ts` sets `environment: "jsdom"`, `globals: true`, and a setup file at `src/test/setup.ts`. The setup file stubs `window.scrollTo` and `window.matchMedia` so components that depend on them render without errors. Tests are discovered from `src/**/*.{test,spec}.{ts,tsx}`.

## Validation rules

The system validates inputs with Zod schemas in `src/lib/validation.ts` and `src/lib/permission-schema.ts`. The following table summarizes the key rules.

| Field / Schema | Rule | Error message |
| --- | --- | --- |
| Email (all) | Trim, lowercase, 3 to 190 chars, valid format | "Enter a valid email address." |
| Password | 12 to 128 chars, lowercase, uppercase, number, symbol | "Password must contain at least 12 characters, a lower-case letter, an upper-case letter, a number, a symbol." |
| Login password | 1 to 200 chars | "Enter your password." |
| Person name | Trim, 2 to 120 chars, letters/spaces/periods/apostrophes/hyphens only | "Enter your full name." / "Names must be 120 characters or fewer." / "Use letters, spaces, periods, apostrophes or hyphens only." |
| Department | Trim, 2 to 190 chars | "Enter your department or office." / "Department must be 190 characters or fewer." |
| Registration OTP email | Must be `@lyceumalabang.edu.ph` | "Use your @lyceumalabang.edu.ph address." |
| Registration OTP code | Exactly six digits | "Enter the six-digit verification code." |
| Recovery code | Exactly six digits | "Enter the six-digit recovery code." |
| Philippine mobile number | 11 digits starting with `09`, or `+63` format | Invalid numbers return `null`; empty input returns `""` |
| Request destinations | Array, 1 to 10 items, 2 to 200 chars each, no control characters | "Enter your destinations." / "You can add up to 10 destinations." / "Destinations contain invalid characters." |
| Passengers | Integer, 1 to 60 | "Enter the number of passengers." / "Enter a whole number of passengers." / "Enter at least one passenger." / "For more than 60 passengers, please file separate requests." |
| Date range | `YYYY-MM-DD` format, end date on or after start date | "Choose a valid date." / "The end date must be on or after the start date." |
| Time needed | `HH:MM`, 24-hour | "Choose the time the vehicle is needed." |
| Purpose | Trim, 5 to 1000 chars, no control characters | "Describe the purpose of travel (at least 5 characters)." / "Purpose must be 1,000 characters or fewer." / "Purpose contains invalid characters." |
| Vehicle plate number | Trim, uppercase, 2 to 32 chars, letters/digits/spaces/hyphens only | "Enter the plate number." / "Plate numbers may use letters, digits, spaces and hyphens only." |
| Request id | Valid UUID | "Invalid request reference." |
| Signature image | `data:image/png` or `data:image/jpeg`, min 50 bytes, max 2 MB | "A signature is required." / "The signature image is too large." / "The signature image is not valid." |
| Trip ticket image | `data:image/png`, min 100 bytes, max 6 MB | "The trip ticket photo is missing." / "The trip ticket photo is too large." / "The trip ticket photo is not valid." |
| Rejection reason | Trim, 5 to 1000 chars | "Please give a reason (at least 5 characters)." / "The reason must be 1,000 characters or fewer." |
| Destination search | Trim, 3 to 100 chars | "Enter at least 3 characters to search previous destinations." / "Search text must be 100 characters or fewer." |
| Analytics path | Trim, 1 to 180 chars, safe path characters only | "Invalid analytics path." |
| Permission Slip department | Trim, 2 to 190 chars | "Enter your department or office." / "The department or office name is too long." |
| Permission Slip date | `YYYY-MM-DD`, valid calendar date | "Choose a valid date." |
| Permission Slip time out / time in | `HH:MM`, 24-hour | "Choose a valid time out." / "Choose a valid time in." |
| Permission Slip reason | Trim, 5 to 500 chars | "State the reason for going out." |
| Permission Slip signature | `data:image/png` or `data:image/jpeg`, min 100 bytes, max 2 MB | "An electronic signature is required." / "The signature image is too large." / "The signature image is not valid." |
| Permission Slip receipt | `data:image/png`, max 4 MB | "The permission slip file is too large." / "The permission slip file is not valid." |
| Permission Slip signatory email | `@lyceumalabang.edu.ph`, valid format, max 190 chars | "Enter a valid institutional email." / "Use your @lyceumalabang.edu.ph address." |
| Permission Slip signatory name | Trim, 2 to 120 chars, letters/spaces/periods/apostrophes/hyphens only | "Enter the signatory's full name." / "Names must be 120 characters or fewer." |
| Trip archive filters | Date range optional; if both provided, end must be on or after start; page 0 to 10000 | "The end date must be on or after the start date." |

## Manual user acceptance test checklist

Run through the checklist below on a staging environment before each production release.

<Steps>
  <Step title="Run automated suite">
    Execute `npm test` and confirm all 161 cases pass. Run `npm run lint` with zero errors.
  </Step>
  <Step title="Build verification">
    Run `npm run build` and confirm the production bundle compiles without errors.
  </Step>
  <Step title="Vehicle submission and approval">
    Create a VRTT request as a requisitioner. Verify the Head of Transport reviews, the Director recommends, and the President approves. Confirm the QR code appears on the approved ticket and that `/api/verify-ticket/$token` validates it.
  </Step>
  <Step title="Return and resubmission">
    Return a request at the review stage with a reason. Confirm the requisitioner can edit and resubmit. Verify prior signatures are archived and the attempt counter increments.
  </Step>
  <Step title="Trip ticket email and print">
    After approval, send the trip ticket image via email. Confirm the inline PNG is delivered to the requester. Test retry from the print page.
  </Step>
  <Step title="COE request and document release">
    Submit a COE request, move it through processing to ready-for-pickup, and release it. Verify the released document is accessible only to admins and that the employee receives status emails.
  </Step>
  <Step title="COE template and compensation">
    Request a COE with the compensation option selected. Verify the amount is rendered in words on the generated template.
  </Step>
  <Step title="Permission Slip approval and receipt">
    Submit a Permission Slip, approve it as the director, and send the receipt. Confirm the PNG receipt is archived and emailed to the employee.
  </Step>
  <Step title="Attendance synchronization">
    Trigger a sync for each staff group (Non-Teaching, College, Basic Ed). Verify the June-to-May cycle is respected and that employee names map correctly from the Google Sheets.
  </Step>
  <Step title="Attendance discrepancy resolution">
    Raise a discrepancy flag from the employee page. Resolve it from the admin page and confirm the notification is marked read.
  </Step>
  <Step title="Role-based access">
    Log in as each role (requisitioner, department head, transport head, director, president, transport staff, guard, driver, admin, super admin) and confirm visible menus and queues match role permissions.
  </Step>
  <Step title="Password policy and lockout">
    Attempt login with 5 wrong passwords. Confirm the account locks for 15 minutes. Test a password change with a valid 12-character mixed password.
  </Step>
  <Step title="Google sign-in">
    Sign in with an institutional Google account. Confirm profile completion prompts for new accounts and redirect safety for same-site paths.
  </Step>
  <Step title="Gmail sender authorization">
    On staging, verify the Gmail sender is connected via `/api/gmail/connect` and that mail delivery reflects `email_status` as sent.
  </Step>
  <Step title="Receipt archive and bulk download">
    As a super admin, search receipts by name and date range. Preview VRTT, COE, and Permission Slip receipts. Download a bulk ZIP and confirm all selected files are included.
  </Step>
  <Step title="Responsive layouts">
    Test dashboard, request forms, approval screens, and COE pages on desktop (1920px), tablet (768px), and mobile (375px) viewports.
  </Step>
  <Step title="External COE access">
    Sign in as a former employee with a personal Google account. Confirm access is limited to `/hrdo/profile`, `/hrdo/coe`, and `/hrdo/coe/$id`.
  </Step>
  <Step title="Database setup on clean environment">
    Run `npm run db:setup` against a fresh MySQL instance. Confirm the database, limited user, schema, and `.env` are created. Run `npm run db:seed` and verify the initial admin account is created.
  </Step>
  <Step title="Security headers">
    Verify CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, and Permissions-Policy are present on all responses.
  </Step>
</Steps>
